## 🏗️ What I Build — Selected Work

### 🔒 [Agbejo](https://github.com/elshaddaioheha/agbejo) — Trustless P2P Transaction System
> `TypeScript` · `Hedera` · `React` · `Smart Contracts`

Peer-to-peer transactions with **zero middlemen**. Agbejo uses smart contracts on Hedera as a neutral arbiter — funds are locked in escrow and only released upon **cryptographically-verified mutual agreement**. A practical answer to the trust problem in digital commerce.

---

### 📅 [Talllie Reservation API](https://github.com/elshaddaioheha/talllie-reservation-api) — High-Concurrency Booking Engine
> `Node.js` · `PostgreSQL` · `Interactive Transactions`

Restaurant booking systems fail when two users click "Reserve" simultaneously. This one doesn't. Built with **atomic PostgreSQL transactions** to eliminate race conditions, and a custom **"Best-Fit" seating algorithm** that dynamically optimizes table allocation under load. No double-bookings. Ever.

---

## 🧠 Engineering Philosophy

```
The difference between a coder and an engineer
is how they handle failure scenarios.
```

My approach is built on three principles:

- **Failure-first design** — I model what can go wrong before I model what should go right. Race conditions, network partitions, invalid states — these get first-class architectural treatment.
- **Concurrency is a first-class citizen** — I don't treat high-traffic as an edge case. Atomic transactions, optimistic locking, and careful state management are standard, not afterthoughts.
- **Architecture over implementation** — A well-designed system outlasts any specific technology. I invest in patterns (DDD, layered architecture, SoC) that remain readable and maintainable as teams and requirements evolve.
